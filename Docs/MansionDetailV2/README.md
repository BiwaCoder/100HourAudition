# 邸宅ディテール更新の確認

参考イメージを先に作成し、噴水・柱・ヤシ・花壇をBlenderで作り直してSeasideMansionへ配置しました。元モデルと旧装飾を保持しています。

- `courtyard.png`, `fountain.png`, `plants.png`, `ocean.png`, `exterior.png`: Unityでの最終形状確認。
- `*-before.png` / `*-after.png`: 同じカメラの旧装飾と詳細版。画像は生成イメージではなくUnityの描画です。
- `Verification.txt`: LOD、シェーダー、噴水の衝突、旧装飾の保存、描画比較の結果。

## 負荷の比較

Unity Editor内の960×600オフスクリーン描画＋GPU読み戻しを3フレーム予熱後、12回測定した平均です。Play時のFPSや製品ビルドのフレーム時間とは異なります。

|視点|旧装飾|詳細版|
|---|---:|---:|
|外観|60.98ms|28.64ms|
|中庭|31.81ms|19.39ms|
|海|12.73ms|15.15ms|

旧装飾1,848オブジェクトを非表示にし、素材単位の結合メッシュと25組のLODへ置き換えました。頂点数は増えますが、外観・中庭ではオブジェクト・描画の分割数が減る効果が出ました。海は約2.4ms増えており、解像度9（13,122三角形）の控えめなOceanメッシュを採用しています。

全素材を同時にLOD0表示すると約66万三角形、LOD1で約24万三角形。実際はカメラ距離と画面占有率で切り替わり、画面外も除外されます。別端末・モバイル・製品ビルドでは未計測です。高解像度Oceanの毎フレームCPU計算や流体シミュレーションは使いません。

編集元と再生成方法は `ArtSource/SeasideMansion/DetailV2/README.md` を参照。

最終Play確認では飛沫93粒が動作（上限256）、速度の各軸設定が一致、水シェーダーのコンパイル成功、RealtimeVoiceセッション0。Consoleエラーなし。確認後はPlay停止・シーン保存済み。`PlayCheck.txt` を参照。
