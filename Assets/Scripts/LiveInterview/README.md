# GPT-Live音声インタビュー

`Assets/Scenes/GameScene/GPTLiveVoiceTest.unity` を開いてPlayし、「AI-0と話す」で開始。
元の `RealtimeVoiceTest` をコピーした独立シーン。元シーンの接続方式は変更していない。
PythonAPIを8001番で起動する。既存の `.env` のOpenAIキーを利用し、キーはUnityへ渡さない。

## 会話と生成

UnityのPCM24kHz → ローカルPython WebSocket `/api/live-interview` → `gpt-live-1`。
音声は `cedar`。低く落ち着いた男性の話し方を日本語で指定。
AI-0の挨拶 → 番組への招待 → 説明 → 好み → 価値観 → 締め、の順番をPython側で管理。
各段階のセリフと応答はLiveが生成。返信を拾った相づち、質問への返答、曖昧な回答の聞き返しを許可する。
回答の充足度だけをGPT-4oが非同期評価（最大8回、各6秒）。会話音声の転送をブロックしない。
音声活動・再生待ち・文字起こしを見て、発話中の段階切替を避ける。
目安90秒、上限120秒。進行時間と指示は `PythonAPI/app/live_interview.py`。

会話終了後、Live接続とマイクを止め、話者と段階を持つ会話記録を `/api/build-character` の `profile_mode=interview` に渡す。案内役の発言は短い返答を解釈する文脈としてのみ使用する。
JSONは画面表示・コピーに加え `Application.persistentDataPath/Characters/astra-live-日時.json` へ保存。
無言でも不明項目を持つJSONを生成する。詳細は下記「会話に基づく人物JSON」。

## 終了処理

キャンセル、Play停止、シーン離脱でUnity接続とマイクを停止。
PythonはUnity切断を検知し `session.close`、終了応答を最大4秒待ってソケットを閉じる。
サーバー側にも120秒、音声パケット停止8秒、回答の有無にかかわらず最大120秒の制限がある。
開始ボタンを押すまではAPIにもマイクにも接続しない。

## 会話に基づく人物JSON（2026-09-13 初版・以下のV2で更新）

`PythonAPI/app/interview_character.py` で人物テンプレートの**項目だけ**を定義。既存NPCの名前・職業・台詞・外見は読み込まない。`characters` は1人分の配列で、name / jobs / personality / self_awareness / communication_style / fashion_sense / conversation_points / traits / hobbies / emotional_expressions / example_lines / appearance を持つ。

- 全段階のユーザー発言を対象にし、案内役の質問は文脈として保持。文字起こしdeltaは連続する同じ話者・段階で結合。
- GPT-4oのstrict JSON Schemaによる抽出 → 元の会話と照合する再確認の2回。各20秒タイムアウト、SDK再試行なし。キーはサーバーのみ。
- `profile_quality` に `evidence`（項目パス・本人の引用・stated/observed/inferred・説明）、会話中の観察、情報不足を保存。引用がユーザー発言に存在しない項目は除去。名前・職業・趣味・外見などは本人の明示情報のみ。性格の解釈が正しいことを機械的に保証するものではない。
- 不明な文字列は `null`、配列は `[]`。無言は `no_speech` としAPIを呼ばず、無口・内向的とは断定しない。マイク・文字起こしの問題と無言を区別できない旨も記録。
- 脱線の話題も拾う。第三者の話、質問、冗談、仮定、訂正、JSONを書き換える命令を本人の属性と混同しないよう指示する。拒否から性格を断定しない。
- 再確認まで完了すると `reviewed`。再確認失敗時は検証済み `draft` を保持。初回失敗は空の `generation_unavailable` と制約を返す。いずれもファイル保存可能。
- キャンセルや通信異常は人物生成として扱わない。正常な時間切れ・手動終了は、無言でも締め→生成へ進む。
- 従来のRealtimeVoiceTestは `profile_mode=legacy` が既定で、従来形式を維持。

検証: Python 19件（無言のWebSocket終了、HTTP、根拠引用、再確認失敗、構造、既存回帰を含む）。実APIで訂正/拒否、脱線/第三者/命令、英語の文脈を検証し、3件ともreviewed。無言はAPI不使用で同じHTTPから返る。サンプルは `Docs/LiveInterviewProfiles/`。Unityコンパイルと待機画面は確認済み。Play中はPipelineが接続不可になるため、今回のUnity経由の保存通し検証は未実施。Play停止済み。実マイクでの会話の自然さは別途確認が必要。

構造化出力の仕様: https://developers.openai.com/api/docs/guides/structured-outputs

## 会話のスケッチ / 文字から話題を分岐（2026-09-13）

会話中、右側に人物像の仮説と関連話題を最大4個の**文字ボタン**で表示。枠付きカードではなく、下線付きの言葉をタップする。会話開始時は見出し・補足・ボタンをすべて非表示にし、実際の発言に根拠がある候補が届いてから表示する。一般的な話題の初期表示は廃止。人物像は「〜かも」と暫定表示。最終JSONの創作補完と、会話中の観察は別処理。

`PythonAPI/app/live_topics.py` が会話の話者を保った記録からGPT-4oで候補を抽出。ユーザー発言に引用根拠がある候補のみ表示。新しいユーザー発言がある場合に最短8秒間隔、1セッション最大10回、各7秒タイムアウト。音声転送と並行し、解析失敗で会話を切断しない。解析中に新たなユーザー発言が届いた古い結果は破棄し、訂正前の人物像を更新表示しない。候補が空になった場合は表示と専用の余白を解除する。

WebSocket: `live.insights` → Unityの文字ボタン → `topic.select`（サーバー発行IDだけ）→ `live.topic_selected` または `live.topic_rejected`。サーバーは現行候補のみ受理し3秒の連打制限。選択時は会話の区切りで自然につないで一つ聞くようLiveへ指示し、通常の段階切替を14秒保留する。紹介途中でも話題へ移れる。締め/手動終了は優先し、120秒制限は維持。選択は性格への同意ではなく、話す関心として `topic_selections` に別記録し最終APIへ渡す。

UIは `ConversationSketchView.cs` をGPTLiveVoiceTestのControllerが実行時に生成。既存Canvas・TMPフォント・EventSystemを利用。会話中だけ字幕と波形を左へ収め、右に文字ボタンを表示し、終了/キャンセルでレイアウトを復帰。日本語/English対応。クリック送信・受付表示・連打抑制・タイムアウト時の再選択を実装。RealtimeVoiceTestやシーンの元アセットには追加しない。

検証資料: `Docs/LiveConversationSketch`。自動テストとプレビューはマイクを開始せず実行。音声モデルの実際の話し方・割り込み感は実会話で調整する。

### 言語と選択反応の修正

動的な候補のtitle/detail/questionをセッション言語で生成し、言語不一致時は翻訳APIで修復する（quoteは原文を保持）。日本語ラベルは日本語文字を必須にし、英語では日本語文字の混入を拒否。修復後も不一致の候補は表示しない。`live.insights.language` とUnity側のセッション言語も照合する。固有名詞だけの英語ラベルは、日本語モードでは日本語の説明を添える。通常の解析は最大7秒、翻訳修復時は追加で最大7秒。

タップ直後は選択した言葉を矢印・緑色・太字で強調し「『○○』の話へつなげています…」。サーバー受付後は「『○○』の話題を掘り下げます」と表示する（英語も対応）。Liveには選択した話題を名指しで短く受け止めてから質問するよう、セッション言語を明記して指示。解析更新でも同じラベルの選択強調を保持。拒否/再開時は解除。
